# Bolh — документ продукта

Версия 1.0 · Составлен по итогам проектной сессии
Назначение: единый источник правды для разработки. Класть в корень репозитория, использовать как контекст для Claude Code.

---

## 1. Что это

**Bolh** (ингушское «болх» — работа, труд) — приложение для управления целями, привычками и деньгами.

**Позиционирование: реалистичный трекер.**
Конкуренты считают достижения — хвалят, рисуют серии, раздают очки и уровни. Bolh считает реальность: где человек находится на самом деле, куда он придёт при нынешнем темпе и во сколько ему это обходится во времени и деньгах.

Из этого следует тон всего продукта. Никаких «Молодец!», никаких поздравительных экранов, никаких значков за десять дней подряд. Только цифры и следствия из них.

**Для кого.** Первая версия делается автором для себя. Далее — публичный продукт. Проектные решения принимаются как для продукта, а не как для личной утилиты.

**Чего в приложении не будет никогда:** рекламы, продажи данных, тёмных паттернов удержания, уведомлений вида «ты пропустил, вернись».

---

## 2. Три блока и их связь

| Блок | Суть | Горизонт |
|---|---|---|
| Цели | Крупные долгосрочные результаты со сроком, этапами и задачами | Месяцы и годы |
| Привычки | Повторяющиеся действия, полезные и вредные | День |
| Финансы | Счета, доходы, расходы, копилки | Месяц |

Плюс четвёртый раздел — **Статистика**, который не имеет своих объектов и показывает срез по всем трём.

**Связи между блоками опциональны.** По умолчанию блоки живут отдельно и полезны сами по себе. Пользователь связывает их сам, когда захочет. Ни одна связь не навязывается и не включается автоматически.

## 3. Принципы проектирования

Эти правила имеют приоритет над отдельными хотелками. При конфликте требований решение принимается в их пользу.

1. **По умолчанию всё выключено.** Приложение работает голым и простым. Любая надстройка включается пользователем из одного места. Никаких мастеров настройки при первом запуске.
2. **Ежедневное действие — самое быстрое в приложении.** Отметить привычку и записать трату должно занимать секунды. Всё редкое (создание, настройка, анализ) может быть медленнее.
3. **Быстрое создание, расширенное по кнопке.** У каждой сущности есть короткая форма из двух-трёх решений и отдельный экран расширенных настроек.
4. **Правда по запросу, а не в лицо.** Неприятные выводы показываются там, куда человек зашёл сам. На главный экран они не выносятся, в уведомления — никогда.
5. **Провал — это данные.** Пропущенный срок и сорванная привычка не наказываются, а используются для уточнения будущих оценок.
6. **Цвет — это язык, а не украшение.** Каждый цвет означает раздел или статус, и значение не меняется от экрана к экрану.
7. **Никакой похвалы.** Приложение сообщает факты. Эмоциональную оценку факту даёт человек.
8. **Локальность.** Данные пользователя лежат на устройстве. Никаких аккаунтов и серверов в первой версии.

## 4. Блок «Цели»

### 4.1 Структура

```
Цель → Этапы → Задачи
```

**Цель** — что-то крупное со сроком: «своё жильё», «нидерландский A2», «форма к лету».
**Этап** — обозримый кусок цели с опциональной датой: «открыть отдельный счёт», «сдать пробный тест».
**Задача** — чек-лист внутри этапа.

### 4.2 Два индикатора вместо одного процента

У цели есть **два разных числа**, и сводить их в одно запрещено — получится цифра, которая скачет без смысла.

- **Прогресс** = закрытых этапов / всего этапов. Отвечает на вопрос «сколько сделано». Дискретный, объективный.
- **Темп** = регулярность за последние 30 дней по привязанным привычкам. Отвечает на вопрос «двигаюсь ли я вообще».

Цель может иметь прогресс 60% и темп 15% — это значит, что человек много сделал и остановился. Это разные диагнозы, требующие разных действий.

### 4.3 Прогноз даты по фактическому темпу *(уникальная механика №1)*

Приложение вычисляет не «сколько пройдено», а **когда человек придёт при нынешней скорости**.

Расчёт:
- **По этапам:** `скорость = закрытых этапов / дней с момента старта`; `дней до финиша = оставшихся этапов / скорость`.
- **По копилке:** `скорость = средний прирост копилки за последние 90 дней (валюта/день)`; `дней до финиша = остаток / скорость`.
- Если есть оба источника — берётся **более поздняя** из двух дат, потому что цель достигнута только когда выполнены оба условия.

Условия включения: минимум 21 день истории цели И (хотя бы один закрытый этап ИЛИ три пополнения копилки). До этого блок прогноза не показывается вообще — приложение не имеет права выдумывать.

Отображение: только внутри карточки цели. Формат — «Октябрь 2028 — на 17 месяцев позже». Если прогноз раньше срока, формулировка нейтральная: «Октябрь 2026 — с опережением на 2 месяца».

### 4.4 Личный коэффициент сроков *(уникальная механика №2)*

Приложение запоминает каждый срок, который человек себе поставил, и сравнивает с фактом.

- Для каждой завершённой цели: `k = фактическая длительность / запланированная длительность`.
- **Коэффициент = медиана всех k** (медиана, а не среднее — устойчивее к выбросам).
- **Включается после 5 завершённых целей.** До этого механика молчит.

Применение при создании новой цели: после выбора даты появляется блок «Проверка срока» с текстом вида «Твой коэффициент — 1,8×. Из 9 поставленных сроков ты уложился в 2. Реалистичная дата для этой цели — ноябрь 2028», и две **равноправные** кнопки: «Оставить май» и «Взять ноябрь 2028». Кнопка отказа не серая и не спрятана — человек имеет право быть оптимистом, и его выбор тоже станет данными.

### 4.5 Цена цели в часах и деньгах *(уникальная механика №3)*

У цели считается реальная стоимость:

- **Время в неделю** = сумма по привязанным привычкам: `плановая частота в неделю × средняя длительность одного выполнения`. Длительность берётся из таймера привычки либо задаётся оценкой при привязке.
- **Деньги в месяц** = плановое пополнение копилки + средние траты за 3 месяца по категориям, помеченным как относящиеся к цели.

Второй уровень механики (версия 2): суммарная проверка перегрузки — «твои три цели вместе требуют 14 часов в неделю и 700 € в месяц». Это бюджет жизни, а не бюджет денег.

### 4.6 Просроченная цель

Когда срок прошёл, а цель не достигнута, приложение **предлагает новый срок, уже скорректированный на личный коэффициент**. Иначе человек передвинет дедлайн ровно на столько же, на сколько ошибся, и цикл повторится. Факт промаха записывается в историю сроков и уточняет коэффициент.

Никакой красной метки «провалено», никаких уведомлений об этом.

### 4.7 Экран «Цели»

- Список крупных карточек с большими отступами. Карточка — самая «воздушная» единица в приложении.
- На карточке: значок, название, срок (цветом, не серым), период «старт → дедлайн», полоса прогресса с процентом, темп цветом по значению (зелёный — высокий, оранжевый — падает, красный — цель стоит), иконки привязанных привычек и копилки в цветах их разделов.
- У ближайшей цели дополнительно строка «Дальше — <название этапа>, <месяц>».
- Порядок сортировки настраивается пользователем: вручную, по сроку, по темпу.
- Цель без этапов показывается свёрнутой — показывать нечего, место не занимается.

### 4.8 Создание цели

Быстрый путь: значок, название, срок. Затем — блок проверки срока (если коэффициент доступен). Затем две сворачиваемые строки: «Этапы» (можно добавить позже) и «Привязать» (копилку, привычки, задачи).

## 5. Блок «Привычки»

### 5.1 Два типа

- **Полезные** — цель в том, чтобы делать.
- **Вредные** — цель в том, чтобы не делать.

На экране это два отдельных раздела, потому что у них принципиально разная логика счёта, и смешивать их в одном списке было бы враньём.

### 5.2 Три режима полезной привычки

Режим выбирается **отдельно для каждой привычки**. По сути это один механизм с разным поведением при пропуске:

| Режим | Поведение при пропуске | Для кого |
|---|---|---|
| Игровой | Серия обнуляется | Нужен азарт и давление |
| С правом на пропуск | 2 дня отдыха в месяц не ломают счёт | Нужен баланс |
| Минимум и норма | Серии как главной метрики нет | Нужна устойчивость |

В интерфейсе режимы подписаны **поведением, а не термином**: «серия обнуляется при пропуске», «два дня отдыха в месяц не ломают счёт», «плохой день не обнуляет прогресс».

### 5.3 Механика «минимум и норма» *(уникальная механика №4)*

У привычки задаются два уровня:
- **Минимум** — действие, которое невозможно не сделать: «одна страница», «надеть кроссовки и выйти за дверь», «одно предложение».
- **Норма** — то, ради чего привычка заведена: «20 страниц», «пробежка 30 минут», «500 слов».

При отметке доступны **две кнопки, и обе засчитывают день**. Плохой день не превращается в ноль, цепочка держится.

Статистика ведёт две линии:
- **Постоянство** — доля дней, когда сделано хоть что-то. Строит привычку.
- **Глубина** — доля нормы среди выполненных дней. Даёт результат.

Дополнительные правила:
- Вечернее напоминание предлагает **минимум**, а не норму: «одна страница, и день засчитан».
- После двух пропусков подряд планка автоматически опускается до минимума на неделю (режим восстановления), чтобы человек вернулся, а не бросил.

### 5.4 Вредные привычки — два режима

- **Счётчик:** «9 дней без срыва». Растёт сам, пока пользователь не нажмёт «срыв».
- **Лимит:** «не больше 3 раз в неделю», счётчик 2 из 3.

Опционально у вредной привычки задаётся **стоимость одного случая**. Тогда приложение показывает накопленную экономию («9 дней без — сэкономлено 74 €») и, если пользователь включил связь, переводит эту сумму в копилку под цель.

### 5.5 Расписание

- Каждый день
- Выбранные дни недели
- N раз в неделю

На быстром пути создания доступны первые два. «N раз в неделю» — в расширенных настройках.

### 5.6 Напоминания

Настраиваются отдельно у каждой привычки: время, включение/выключение, вечерний повтор с предложением минимума. Локальные уведомления телефона, сервер не нужен.

### 5.7 Пауза и отпуск

Привычку можно поставить на паузу на период (болезнь, отпуск, переезд). Дни паузы **исключаются из знаменателя** статистики — они не считаются ни выполненными, ни пропущенными. В интерфейсе это описано через последствие: «статистика не пострадает».

### 5.8 Экран «Привычки»

- Сверху — **общая недельная полоса**: семь колонок с днём недели и датой, сегодняшний день подсвечен. Тап по прошлому дню открывает его и позволяет исправить отметку.
- Ниже — строки без карточек, с тонкими разделителями и большими вертикальными отступами.
- В строке: значок, название, одна строка контекста (серия / N из 30 дней / N из 3 за неделю), справа одно действие.
- Действие — круглая кнопка отметки. Круг, а не квадрат: читается как действие, а не как ячейка таблицы.
- У привычки в режиме минимума вместо круга две компактные кнопки «мин» и «норма», видимые только пока день не отмечен; после отметки они схлопываются в круг.
- Вредные привычки — отдельный раздел ниже, без недельной сетки, с кнопкой «срыв» или «+1».

### 5.9 Создание привычки

Быстрый путь — **три решения**: значок и название в одной строке, полезная или вредная, как часто (каждый день / дни недели). Ниже — строка «Расширенные настройки» (режим, минимум и норма, напоминание, привязка к цели, категория, пауза).

Сверху — **библиотека шаблонов**: подъём, спорт, чтение, вода, отказ от курения и т.д. В шаблоне уже заполнено всё, включая разумные минимум и норму. Один тап — привычка готова.

Обоснование: люди отваливаются не на отметке, а на создании. Восемь решений ради «пить воду» убивают продукт.

## 6. Блок «Финансы»

### 6.1 Состав

Счета, доходы, расходы, копилки под цели.

### 6.2 Ввод данных

**Первая версия — только вручную.** Быстрый ввод плюс расширенный.

Подключение банка через PSD2-агрегатора (GoCardless, Tink, Plaid) и импорт выписки — вторая версия. Оба варианта требуют юрлица, договора и другого уровня требований к безопасности.

### 6.3 Валюты

Мультивалютность с автоматическим курсом.

**Правило курса, обязательное к исполнению:** курс фиксируется **на дату операции** и больше никогда не меняется. Текущие остатки на счетах пересчитываются по свежему курсу. Если пересчитывать историю по сегодняшнему курсу, прошлый месяц будет «дорожать» и «дешеветь» сам по себе — это ломает доверие к цифрам.

Источник курсов — ежедневные публичные данные ЕЦБ. Кэшируются локально; без сети используются последние известные.

### 6.4 Категории

Готовый набор плюс пользовательские. У каждой значок и цвет.

### 6.5 Регулярные платежи

Настраиваются вручную: название, сумма, счёт, категория, периодичность. **Уведомление приходит за день до списания, в нём кнопка «записать»** — нажал, операция создалась. Ничего не появляется в истории без ведома человека.

Платёж может быть **разовым**: тот же платёж без повтора, с датой вместо периодичности — например, оплатить что-то через неделю. Напоминание приходит так же; после «записать» или «пропустить» разовый платёж уходит из списка, а не переезжает на следующий период.

### 6.6 Копилки

Копилка привязывается к цели. Тип выбирает пользователь:
- **Виртуальный конверт** (по умолчанию) — деньги физически на обычном счёте, но приложение помнит, что сумма зарезервирована, и вычитает её из «доступно потратить».
- **Просто цифра** — «надо 5000, накоплено 1200», без связи с балансом.

Отдельный банковский счёт не является третьим режимом: если он есть, он уже заведён в приложении, и цель просто привязывается к нему.

### 6.7 Бюджеты и лимиты

Подключаемая опция. Лимиты по категориям с предупреждениями. По умолчанию выключены.

### 6.8 Экран «Финансы»

Стиль — приборная панель. Без карточек, только тонкие горизонтальные разделители: экран читается как выписка, что уместно для денег.

- Сверху крупно **общий баланс** моноширинными цифрами, под ним строка «N € зарезервировано в копилках» (обязательно: иначе человек считает своими деньги, уже обещанные цели).
- Ряд счетов с суммами.
- Расходы за месяц: **кольцевой график** слева, легенда справа. Категории окрашены оттенками синего; категория, выросшая аномально, окрашивается красным — цвет несёт смысл, а не порядок в списке.
- Переключатель «Круг / Список / Динамика».
- Опция «без обязательных трат»: убирает аренду и прочие фиксированные платежи, чтобы круг показывал только ту часть денег, где решения принимаются каждый день.
- Ближайший регулярный платёж с кнопкой «записать».
- Строка копилки со значком **цвета раздела целей**.

Все числа — моноширинные, выровнены по правому краю, чтобы суммы сравнивались глазом без чтения.

### 6.9 Запись траты

Живёт в нижней шторке, а не на отдельном экране — это самое частое действие в приложении.

Быстрый путь: тип (расход/доход), сумма крупно, категория чипами, счёт. Кнопка «Записать». Ниже строка «Дата, заметка, привязка к цели» — расширенный вариант.

## 7. Статистика

Отдельная вкладка. Своего цвета не имеет — раздел не про себя, а про все три, поэтому его иконка в навигации нейтральная. Каждый блок внутри окрашен цветом своего раздела.

Периоды: неделя, месяц, год. **По умолчанию — месяц.**

Содержимое:
- Три метрики в строку, окрашенные по разделам: выполнение привычек (фиолетовый), расходы (синий), цели в темпе (бирюзовый).
- График выполнения привычек по неделям со сравнением к прошлому периоду. Столбики темнее в прошлом, ярче ближе к сегодня.
- Расходы по категориям с дельтой к прошлому периоду.
- Блок «Выводы».

### 7.1 Правила выводов

В первой версии ИИ нет. Выводы генерируются **по правилам, локально**. Показывается **максимум два за раз**.

Главное правило: вывод имеет право на существование, только если человек не увидел бы этого сам, глядя на график. Поздравления и констатации («ты выполнил 5 привычек!») — шум, после которого статистику перестают открывать.

Два типа правил:

**Межблоковые** (невозможны в отдельных приложениях):
- Категория трат выросла на >50% И связанная вредная привычка выполнялась <50% дней → «Доставка выросла на 83%. Привычка отказа держалась 9 дней из 30».
- Темп цели упал >30% за месяц → «Цель X стоит третью неделю. Привязанные привычки выполняются на 20%».
- Пополнение копилки замедлилось → сдвиг прогнозной даты.

**Внутриблоковые:**
- Постоянство высокое, глубина низкая → «Чтение идёт 24 дня из 30, но 19 из них на минимуме. Постоянство есть, глубины нет».
- Привычка выполняется только в определённые дни недели → «Зал случается только по вторникам и пятницам, хотя запланирован на три раза».
- Расход в категории аномален относительно своей же истории за 3 месяца.

Когда появится ИИ-слой, он встанет ровно на это место. Механика остаётся, качество выводов растёт.

## 8. Данные

### 8.1 Хранение

Только на устройстве. SQLite через Room. Никаких аккаунтов, серверов и обязательной регистрации.

**Следствие, обязательное к реализации:** потеря телефона = потеря всех данных, поэтому **экспорт и резервная копия нужны в первой версии**, а не потом. Экспорт в JSON и CSV, импорт из своего же формата.

**Задел под облако:** схема данных проектируется пригодной к синхронизации сразу — у каждой записи UUID, `created_at`, `updated_at`, мягкое удаление (`deleted_at`). Иначе переезд в облако станет переписыванием половины приложения.

### 8.3 Ключевые вычисления

```
темп_привычки(30д)   = выполненных дней / запланированных дней
                       (дни паузы исключаются из знаменателя)

глубина(30д)         = дней с нормой / дней с любым выполнением

темп_цели            = среднее темпов привязанных привычек

прогресс_цели        = закрытых этапов / всего этапов

скорость_этапов      = закрытых этапов / дней от старта
скорость_копилки     = прирост за 90д / 90

прогноз_даты         = max(дата_по_этапам, дата_по_копилке)
                       требует: ≥21 день истории И (≥1 этап ИЛИ ≥3 пополнения)

k_цели               = факт_длительность / план_длительность
коэффициент_сроков   = медиана(k) по завершённым целям, при N ≥ 5

цена_времени         = Σ (частота_в_неделю × estimatedMinutes)
цена_денег           = plannedMonthly + средние траты за 3 мес по связанным категориям
```

## 9. Интерфейс

### 9.1 Навигация

Нижняя панель, четыре вкладки: **Цели · Привычки · Финансы · Статистика**. Активная вкладка окрашивается цветом своего раздела — переключаясь, человек видит смену цвета и всегда знает, где находится.

Главный экран при запуске — **Цели**.

Кнопка «+» всегда означает **создать** (трата, привычка, задача, цель). Отметка привычки делается на её вкладке в один тап, без меню. Редкое действие может стоить лишнего касания, ежедневное — нет.

### 9.2 Три характера, одна система

Общее для всех разделов: шрифт, скругления, отступы, тёмный фон, нижняя навигация, кнопка создания, тон текстов.

Разное:

| Раздел | Характер | Форма |
|---|---|---|
| Цели | Карта пути | Крупные карточки, много воздуха, большая типографика |
| Привычки | Пульт | Строки с тонкими разделителями, недельная полоса сверху, крупные зоны нажатия |
| Финансы | Приборная панель | Строки-выписка, моноширинные цифры, кольцевые графики, табличная плотность |

### 9.3 Цвет

Три **соседних** цвета на круге, а не противоположных: разделы ощущаются разными, но родными. Разница читается боковым зрением, но не режет глаз при переключении.

| Роль | Цвет | Пример |
|---|---|---|
| Цели | Бирюзовый | `#5DCAA5` |
| Привычки | Фиолетовый | `#7F77DD` / `#534AB7` |
| Финансы | Синий | `#85B7EB` / `#378ADD` |
| Внимание | Оранжевый | `#EF9F27` |
| Проблема | Красный | `#E24B4A` |
| Успех | Зелёный | `#97C459` |

**Цвет как язык.** Значок привязанной привычки на карточке цели — фиолетовый. Значок копилки — синий. Строка копилки на экране финансов — бирюзовая. Человек читает связь между блоками без единой подписи. Статусные цвета (оранжевый, красный) перебивают цвет раздела: то, что цель встала, важнее того, откуда она.

### 9.4 Тема

Тёмная по умолчанию. Светлая — опция.

### 9.5 Первый запуск

Онбординга нет — сразу в приложение. Следовательно, **пустые экраны обязаны объяснять себя сами**: не «Целей нет», а крупная кнопка «Создать первую цель» с одним примером под ней. То же в привычках и финансах.

### 9.6 Локализация

Русский и английский с первой строчки кода. Ни одного текста прямо в коде, всё через ресурсы. Ретроспективно локализация вкручивается вдвое дороже.

## 10. Технический контур

- **Платформа:** Android первым. iOS — второй этап. Настольная версия — третий.
- **Язык и UI:** Kotlin, Jetpack Compose.
- **База:** Room поверх SQLite, локально.
- **Уведомления:** локальные, WorkManager / AlarmManager.
- **Среда:** Android Studio. Запуск — эмулятор либо телефон по USB с включённой отладкой.
- **Публикация:** Google Play нужен только для публичного релиза (разовый взнос аккаунта разработчика). Для личного использования не требуется.
- **Архитектура:** MVVM, репозитории поверх Room, вычисления (темп, прогноз, коэффициент, цена) вынести в отдельный слой `domain/analytics` — они будут переиспользованы на iOS.

Осознанная цена решения: нативный путь означает две кодовые базы и примерно двух-с-половиной-кратный объём работы против кроссплатформенного, взамен — лучшее ощущение интерфейса и отсутствие зависимости от чужого фреймворка.

## 11. Объём первой версии

Правило резки: **в первую версию входит то, без чего блок перестаёт быть блоком.** Всё, что по ходу проектирования было названо опцией, переезжает во вторую.

### Входит

**Цели:** создание, этапы, задачи, прогресс и темп, привязка привычек и копилки, прогноз даты, личный коэффициент, предложение нового срока, сортировка.
**Привычки:** полезные и вредные, три режима, минимум и норма, расписание (все три варианта), напоминания, шаблоны, быстрое создание, недельная полоса с исправлением прошлых дней, пауза.
**Финансы:** счета, доходы и расходы вручную, категории, мультивалюта с автокурсом, копилки, регулярные платежи с уведомлением, кольцевой график.
**Статистика:** три периода, графики, сравнение периодов, выводы по правилам.
**Общее:** тёмная тема, два языка, экспорт и резервная копия, пустые состояния.

### Не входит (версия 2)

- Подключение банка и импорт выписки
- Бюджеты и лимиты по категориям
- Режим отпуска (пауза отдельной привычки остаётся)
- Автоперевод сэкономленного в копилку
- Суммарная проверка перегрузки по всем целям
- Облачная синхронизация
- ИИ-слой
- Подписка (первая версия бесплатна целиком)
- Собственный календарь встреч
- Светлая тема

## 12. Риски и открытые вопросы

**1. Ключевая механика включается не сразу.** Личный коэффициент требует пяти завершённых целей, прогноз — трёх недель истории. Первые месяцы приложение выглядит как обычный трекер. Нужно решить, чем удерживать человека в этот период.

**2. Категория занята.** Комбинация «привычки + финансы + цели в одном» уже реализована несколькими продуктами, в том числе с подключённым ИИ. На Android есть сильный бесплатный трекер привычек с открытым кодом. Отличием не могут быть «всё в одном» и «без рекламы» — только четыре механики из этого документа.

**3. Ручной ввод трат.** Главная причина смерти финансовых приложений. Первая версия сознательно принимает этот риск, но за ним надо следить: если автор сам перестанет вносить траты через две недели, вопрос о подключении банка становится первоочередным.

**4. Честность против удержания.** Приложение говорит неприятные вещи. Принцип «правда по запросу» снижает риск, но не убирает его. Нужно наблюдать, не начинают ли люди избегать экрана цели.

**5. Три блока — большой объём для одного человека.** Даже в урезанном виде это три подсистемы. Порядок сборки: сначала общий каркас и модель данных, затем привычки (самый простой блок с ежедневным использованием), затем цели, затем финансы, затем статистика поверх готовых данных.

**6. Не решено:** название и содержание подписки во второй версии; нужен ли раздел задач отдельной вкладкой или задачи живут только внутри этапов; формат экрана настроек.
