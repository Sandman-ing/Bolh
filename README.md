# Bolh

Приложение для управления целями, привычками и деньгами. Реалистичный трекер:
считает не достижения, а то, где человек находится на самом деле, куда он придёт
при нынешнем темпе и во сколько ему это обходится.

Единый источник правды по продукту — [BOLH_PRODUCT_SPEC.md](BOLH_PRODUCT_SPEC.md).
Ссылки вида «§5.3» в комментариях к коду указывают на разделы этого документа.

## Как собрать

Нужны JDK 17 и Android SDK 37. На этой машине уже стоят:

- JDK: `C:\Program Files\Microsoft\jdk-17.0.14.7-hotspot`
- SDK: `C:\Users\Jeyrakh\AppData\Local\Android\Sdk` (прописан в `local.properties`)

```bash
cd /c/Bolh && JAVA_HOME="C:/Program Files/Microsoft/jdk-17.0.14.7-hotspot" ./gradlew :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Юнит-тесты ядра:

```bash
cd /c/Bolh && JAVA_HOME="C:/Program Files/Microsoft/jdk-17.0.14.7-hotspot" ./gradlew :app:testDebugUnitTest
```

## Чего пока нет

- Мультивалютность отключена: базовая валюта евро, курсы ЕЦБ не тянутся.
  Схема к ним готова (`rateToBase`, таблица `currency_rates`).
- Счёт и регулярный платёж можно удалить, но не переименовать.
- Своих категорий завести нельзя, работает готовый набор из шестнадцати.
- Пометка категории как относящейся к цели (§4.5, денежная половина цены цели)
  есть в схеме, но не выведена в интерфейс.
- Светлая тема — вторая версия (§11).

## Принятые решения, которых нет в документе

1. **История пополнений копилки** — отдельная таблица `jar_contributions`.
   §4.3 требует прироста за 90 дней и минимум трёх пополнений, а по одному полю
   «накоплено» ни того, ни другого не видно.
2. **Счёт-получатель перевода** — поле `toAccountId` в операции.
3. **Личный коэффициент считается от первого поставленного срока.** Если считать
   от последнего переноса, коэффициент стремился бы к единице и механика тихо
   самоуничтожилась бы.
4. **Нет знаменателя — нет числа.** Цель без этапов не показывает прогресс,
   цель без привычек не показывает темп. Ноль означал бы «стоит», а это враньё.
5. **Значки хранятся строковым ключом**, а не номером ресурса: номера меняются
   при каждой пересборке и ломают экспорт.
6. **Деньги — целое число минорных единиц.** Дробные типы на тысяче операций
   дают расхождение, которое потом невозможно объяснить.
7. **Напоминания неточные** (WorkManager, без `SCHEDULE_EXACT_ALARM`): точность
   до минуты привычке не нужна, а разрешение на точные будильники пугает
   и режется производителями.
8. **Внедрение зависимостей руками** (`BolhContainer`): единственный обработчик
   аннотаций в проекте — Room, и держать его одного дешевле, чем согласовывать
   версии Kotlin, KSP и генератора графа.
9. **Светлая тема отложена** во вторую версию (§11), поле темы в настройках
   заведено под неё заранее.
