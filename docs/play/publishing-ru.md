# Как выпустить Bolh в Google Play

Готовые материалы лежат в этой папке: тексты страницы (`store-listing.md`), политика конфиденциальности (`privacy-policy.md`), значок и обложка. Сборка для Google Play — `C:\Bolh\Bolh-<версия>.aab`. APK в Play не загружается, он только для ручной установки.

## 0. Сначала — копия ключа

`bolh-release.jks` и `keystore.properties` из `C:\Bolh` — это ключ, которым подписываются сборки. Без него нельзя выпускать обновления (сброс ключа возможен только через поддержку Google и занимает время). Скопируй оба файла в два места: например, на флешку и в зашифрованный архив в облаке. Пароль хранится в `keystore.properties`.

## 1. Политика конфиденциальности по ссылке

Google требует ссылку на политику. Самый простой путь без кода:

1. sites.google.com → «Пустой сайт».
2. Название «Bolh — Privacy Policy», вставить текст из `privacy-policy.md` (обе части).
3. «Опубликовать» → придумать адрес → скопировать ссылку. Её вставляешь в Play Console.

## 2. Создать приложение

Play Console → «Все приложения» → «Создать приложение»:

- Название: `Bolh — цели, привычки, деньги`
- Язык по умолчанию: русский (ru-RU)
- Приложение, бесплатное
- Подтвердить декларации (это твоё согласие с правилами Google — отмечаешь сам)

## 3. «Настройка приложения»: готовые ответы

На панели приложения есть список заданий. Ответы для Bolh:

| Раздел | Ответ |
|---|---|
| Доступ к приложению | Все функции доступны без входа и особых условий |
| Реклама | Нет рекламы |
| Возрастной рейтинг | Анкета: категория «Все остальные типы приложений»; насилие, азартные игры, общение между пользователями, передача местоположения, покупки — везде «Нет» |
| Целевая аудитория | 18 лет и старше |
| Новостное приложение | Нет |
| Государственное приложение | Нет |
| Финансовые функции | Приложение только ведёт учёт: не переводит деньги, не даёт займы, не торгует. Если в списке есть пункт про учёт личных финансов или бюджет — отметь его, иначе «нет финансовых функций» |
| Приложение для здоровья | Нет |
| Политика конфиденциальности | Ссылка из шага 1 |
| Безопасность данных | См. ниже |

**Безопасность данных.** На вопрос «Собирает ли приложение или передаёт какие-либо данные пользователей?» — **Нет**. Основание: всё хранится на устройстве, регистрации нет, в сеть уходит только запрос курсов валют без данных пользователя. После ответа «Нет» остальные вопросы раздела не нужны.

## 4. Основная страница в магазине

Раздел «Развитие → Страница приложения → Основная страница»:

- Название, краткое и полное описание — из `store-listing.md`, русская часть.
- Значок — `play_icon_512.png`, обложка — `feature_graphic_1024x500.png`.
- Скриншоты телефона — минимум 2 (подготовлю отдельно).
- Категория «Продуктивность», адрес почты для связи.
- Перевод: «Управление переводами» → добавить английский → английская часть `store-listing.md`.

## 5. Закрытый тест — обязателен для нового аккаунта

Личные аккаунты, созданные после 13 ноября 2023 года, сначала проходят закрытый тест: **не меньше 12 тестировщиков, которые 14 дней подряд остаются в тесте**. Кто вышел раньше, не считается. Бери 15–20 человек с запасом.

1. «Тестирование → Закрытое тестирование» → создать трек.
2. «Тестировщики» → новый список → адреса Google-аккаунтов (те, под которыми у людей Play Маркет).
3. «Создать выпуск» → на вопрос о подписи оставить вариант по умолчанию: ключ хранит Google (Play App Signing) → загрузить `.aab` → примечания к выпуску → «Сохранить» → «Отправить на проверку». Первая проверка может занять от нескольких часов до нескольких дней.
4. После одобрения скопировать ссылку для участия и разослать тестировщикам. Каждый открывает её на телефоне под своим аккаунтом → «Стать тестировщиком» → ставит Bolh из Play Маркета.

**Важно для тех, у кого уже стоит Bolh из APK.** Версия из Play подписана ключом Google, поверх APK она не встанет. Порядок: в Bolh сделать резервную копию в файл → удалить приложение → поставить из Play → восстановить копию.

Эти 14 дней люди должны реально пользоваться приложением: Google это проверяет. Попроси писать отзывы через Play и выпусти за это время одно-два обновления по отзывам — это пригодится в заявке.

## 6. Заявка на рабочую версию

Через 14 дней на панели появится «Подать заявку на доступ к рабочей версии». Три блока вопросов: как прошёл закрытый тест (сколько людей, что использовали, какие были отзывы), о приложении (для кого, чем полезно, сколько установок ждёшь в первый год) и готовность (что изменил по итогам теста). Проверка обычно занимает до 7 дней.

## 7. Выпуск

«Рабочая версия» → «Создать выпуск» → та же или более новая `.aab` → выбрать страны → отправить на проверку. У каждого следующего `.aab` номер версии должен быть выше — это я делаю при сборке.

---

Источник требований к тесту: [Play Console Help — App testing requirements for new personal developer accounts](https://support.google.com/googleplay/android-developer/answer/14151465).
